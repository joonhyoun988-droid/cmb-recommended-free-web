## 3. Real results

### First run — found a real bug, not a fabricated pass

The first execution of the new script failed:

```json
{"status":"FAIL","error":"EPERM, Permission denied: \\\\?\\C:\\...\\.qa-temp\\cmb-shot-V5R8fX '\\\\?\\C:\\...\\.qa-temp\\cmb-shot-V5R8fX'"}
```
`Desktop screenshot failed.` (thrown by `run_cmb_frontend_proof_stack.ps1:133`)

Root cause: `chrome.kill()` returns before Windows fully releases file handles in the temp `--user-data-dir`, so the immediately-following `rmSync(profileDir, ...)` in the `finally` block raced Chrome's own shutdown and threw `EPERM`. Because that error was thrown inside `finally`, it overrode the function's actual outcome — even though `preview_desktop.png` (214,120 bytes) had already been written successfully just before the cleanup step, the process still reported and exited as `FAIL`.

Fix applied to `qa/cmb-screenshot-cdp.mjs`: wait for the Chrome process's `exit` event (capped at 3s) before attempting cleanup, and retry `rmSync` up to 5 times with a 300ms backoff, logging a warning instead of throwing if cleanup still can't complete. The screenshot itself is captured and written before this cleanup step runs, so a cleanup-only failure can no longer be reported as a capture failure.

- Mobile capture via the exact same new script scored a perfect 0% diff against its baseline.

## 4. Why axe/Lighthouse's `npx` calls succeeded while Playwright's did not

Both remain `npx`-based and unmodified. They ran successfully here (`axeViolations: 0`, `lighthousePerformance: 99`) even though `npx playwright screenshot` failed on this same machine. The likely reason: `@axe-core/cli` and `lighthouse` are pure-JS npm packages `npx` can fetch and run directly, whereas Playwright's actual failure mode in this environment is almost certainly its **post-install browser binary download** (a much larger, separate network fetch beyond just resolving the npm package) — which is exactly the kind of "network download" the owner's approval explicitly forbids solving via `npm install`. This is additional evidence that the CDP-based fix (reusing the already-installed local Chrome binary, zero downloads) is the correct minimal fix, rather than trying to make `npx playwright` work.
